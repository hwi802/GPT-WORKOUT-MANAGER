# FitLog 운동 메모 데이터 정리 및 가져오기

## 목적

날짜·종목·중량·반복 횟수가 자유로운 형식으로 적힌 개인 운동 메모를 FitLog의 관계형 데이터 모델에 맞게 정리했다. 실제 기록을 넣어 종목별 최근 기록, 최고 중량 변화, AI 제안과 최근 7일 분석을 검증하는 것이 목표였다.

## 입력 데이터와 변환 원칙

원본 메모는 2026년 3월 16일~10월 8일의 37일치다. 각 종목의 중량 블록과 반복 횟수를 세트별 `(weight, reps)` 행으로 풀고, 메모에 적힌 운동·세트 순서를 유지했다.

| 원본의 특징 | 처리 방식 |
| --- | --- |
| 날짜에 연도가 없음 | 기록 연도가 2026년임을 확인한 뒤 사용 |
| 운동 시각이 없음 | DB에서 시각이 필수라 해당 날짜 **12:00 KST를 임시 값**으로 입력. 실제 운동 시각이라는 뜻은 아님 |
| 같은 종목의 한영 표기가 섞임 | `Chest Press`·`체스트프레스`, `Assist Pull-up`·`어시스트 풀업`처럼 분명히 같은 표기만 통일 |
| 다른 기구나 한쪽 기준 중량이 섞임 | 플레이트 로드·스미스 머신 등은 별도 종목으로 유지하고, 한쪽 기준임이 명시된 항목은 이름에 표시 |
| 중량 또는 횟수가 빠지거나 값이 불확실함 | 값을 추정하지 않고 해당 세트만 보류. 명확한 나머지 세트는 유지 |
| 유산소·맨몸 운동이 포함됨 | 현재 DB가 중량·정수 반복 횟수 세트 중심이어서 별도로 보류 |

보조 풀업·보조 딥스의 kg은 몸에 더한 부하가 아니라 **보조 중량**이다. 보조 중량이 낮아지는 것이 난도 상승일 수 있으므로 단순 최고 중량 그래프를 성장으로 해석하지 않는다.

## 가져오기 과정

1. 메모의 명확한 세트를 별도 검토 파일로 옮기고, 불명확한 항목은 목록에 남겼다.
2. 가져오기 스크립트가 날짜와 중량·정수 반복 횟수를 검증하고, 쓰기 전 미리보기에서 DB와 겹치는 날짜를 보여주도록 했다.
3. 로컬 SQLite 파일을 백업한 뒤 트랜잭션으로 데이터를 저장했다. 같은 날짜에 이미 기록이 있으면 기존 기록을 덮어쓰지 않는다.
4. 기존의 예시·테스트 기록 두 건은 원본 메모와 다른 것을 확인하고 백업 후 제거했다. 스크립트를 다시 실행해 해당 날짜의 실제 메모 기록을 넣었다.
5. 새 종목은 `미분류`로 등록한 뒤, 주요 종목의 부위를 웹에서 설정했다. 실제 개인 기록 파일과 가져오기 초안은 공개 Git 저장소 밖에 보관했다.

## 결과와 확인

- 원본 **37일** 가운데 현행 데이터 모델로 구조화할 수 있는 **36일, 종목 수행 136건, 세트 498개**를 가져왔다. 맨몸·유산소 위주인 8월 23일과 불명확한 일부 세트는 보류했다.
- 같은 날짜의 기존 기록은 미리보기에서 발견하고 의도적으로 처리했다. 가져오기를 반복 실행해도 이미 저장된 날짜가 중복되지 않도록 확인했다.
- `/api/weekly-records`에서 최근 7일의 10월 6일·8일 기록을 확인했다. 과거 기록은 종목별 최근 7회 조회와 최고 중량 그래프에 표시됐다.
- 웹에서 `Chest Press`의 최근 세트와 최고 중량 변화, 스미스 머신 벤치프레스의 10월 3일·6일 기록을 확인했다.
- 로컬 `database/fitlog.db`와 개인 기록 파일은 Git에 포함되지 않으며, 검증 후 작업 트리가 깨끗한 것을 확인했다.

## 남은 데이터 제약

원문에 시각이 없어 최근 7일의 **경계 시각**은 임시 입력 시각의 영향을 받을 수 있다. 현재 중복 검사는 날짜 기준이므로 하루에 실제로 두 차례 운동한 기록은 별도 검토가 필요하다. 맨몸 운동·유산소의 거리·시간 및 세트별 보조 중량을 정확히 표현하고 분석하려면 데이터 모델과 시각화 규칙을 확장해야 한다. 공개 저장소만 내려받은 경우 개인 데이터는 포함되지 않으며, 로컬 DB 초기화 또는 예시 데이터 생성으로 실행할 수 있다.
