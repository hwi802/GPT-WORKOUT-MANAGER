# FitLog 운동 기록 수정·삭제 마일스톤

검증일: 2026-10-07 (한국 시간)

## 목표

웹에서 저장된 운동 기록을 수정하거나 삭제한다. 운동 하나에 여러 종목과 세트가 들어 있으므로, 한 기록의 모든 구성 요소가 함께 변경되도록 처리한다.

## 구현 내용

| 기능 | 동작 |
| --- | --- |
| 수정 시작 | 최근 운동 기록의 `수정` 버튼을 누르면 완료 시각, 운동 종목, 중량, 횟수를 입력 폼에 채운다. |
| 수정 저장 | `PUT /api/workouts/:id`로 해당 기록의 내용을 교체한다. 기존 운동 ID를 유지한다. |
| 수정 취소 | 입력 중인 변경을 버리고 새 기록 입력 화면으로 돌아간다. 변경된 입력이 있으면 확인창을 띄운다. |
| 삭제 | `DELETE /api/workouts/:id`를 호출한다. 삭제 전에 날짜와 운동 종목을 보여 주는 확인창을 띄운다. |
| 목록 갱신 | 수정·삭제 후 최근 운동 기록과 이전에 수행한 운동 종목 목록을 다시 불러온다. |

서버는 Node.js, MCP SDK, SQLite(`node:sqlite`)를 사용한다. 웹 UI는 별도 프레임워크 없는 HTML, CSS, JavaScript로 구성된다. 기존 `get_recent_workouts`, `save_workout` MCP 도구를 유지하면서 웹 API에 수정·삭제 경로를 추가했다.

### 데이터 처리

수정할 때 기존 `workouts.id`는 유지하고, 완료 시각을 갱신한 뒤 기존 종목·세트를 교체한다. 삭제할 때는 `workout_sets` → `exercises` → `workouts` 순서로 제거한다. 두 동작 모두 SQLite 트랜잭션 안에서 처리하므로 중간에 오류가 발생하면 롤백된다. 수정 입력에는 기존 저장 API와 같은 날짜·종목·중량·횟수 검증을 적용한다. 존재하지 않는 기록은 404를 반환한다.

## 검증 결과

### 사용자 PC의 실제 브라우저 검증

1. 하나의 기록에 `테스트1` 3세트와 `테스트2` 1세트가 저장된 상태에서 `테스트1` 첫 세트의 중량을 **10kg에서 12kg으로 수정**했다. 나머지 세트와 `테스트2`는 유지됐다.
2. 다시 수정 화면에서 값을 바꾼 뒤 **수정 취소**했다. 최근 기록에는 **12kg**이 유지됐다.
3. 삭제 확인창에 해당 날짜와 `테스트1, 테스트2`가 표시됐다. 삭제 확인 후 최근 운동 기록 수가 **3건에서 2건**으로 줄었고, 기존 **벤치 프레스** 기록은 남아 있었다.

### 분리된 임시 DB 검증

사용자 데이터와 별개의 SQLite DB에서 수정 후 동일 ID 유지, 자식 세트 교체·삭제, 없는 기록과 잘못된 입력 거부, 수정·삭제 도중 오류를 강제로 일으켰을 때 롤백, 삭제 후 MCP 조회 결과 반영을 확인했다. 이 검증 코드는 프로젝트에 추가하지 않았다.

## 현재 범위와 다음 작업

- 웹 화면은 최근 **10건**을 표시한다. 전체 기록 탐색과 검색은 후속 작업이다.
- 동시에 여러 탭에서 같은 기록을 수정하는 경우 충돌 감지는 아직 없다.
- GitHub 포트폴리오 정리 시 이 검증 결과를 README 기능 설명과 화면 캡처에 반영한다.
- 실제 사용 DB(`database/fitlog.db`)는 기록 데이터다. Git 추적 여부를 확인하고, 소스 변경과 분리해 관리 방침을 정한다.
